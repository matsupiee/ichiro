# プロフィール写真をアップロードできる

> ステータス: 実装済み

## ストーリー

ログイン中のユーザーとして、プロフィール写真を選んでサーバーに保存したい。
手元の写真を、自分で形式やサイズを変えずに選びたい。
ほかのブラウザやパソコンでログインしても同じ写真が出て、自分のアカウントだと分かりやすくなるから。

## 動作確認の手順

`bun run db:seed -- --url file:/絶対パス/対象.sqlite --skip-migrations` でデモデータを入れ、`bun run dev:server` を起動する。
ブラウザで http://localhost:3000/app を開き、demo@ichiro.app / password123 でログインしておく。デモユーザーは写真なしで始まる。
確認用に、手元に JPEG・PNG の写真（縦長や横長のものを含む）を用意する。

1. ホームの右上のアカウントのボタンを押し、アカウント画面の「プロフィール写真」の行を押す。
   - 写真が未登録の場合、ホームの右上の丸ボタンの中央に人型アイコンが表示される。
   - 「写真を選択」「削除」のメニューが出る。
   - → [アカウント画面でアカウントを管理できる](./profile-sheet.md)
2. 「写真を選択」を押して写真のファイルを選ぶ。
   - ファイルの選択は画像だけに絞られる（`accept="image/*"`）。ブラウザで読める形式なら選べる。Safari では HEIC も選べる。
   - 切り抜きの画面は出ない。写真の中央が正方形に切り抜かれる。
   - 選んだ写真がすぐに行のアイコンに出て、アップロードが終わるまで白いくるくるが重なる。
   - アップロード中は「プロフィール写真」の行を押せない。
   - 終わるとくるくるが消え、写真はそのまま残る。ホームの右上にも同じ写真が出る。
3. ページを読み込み直す。別のブラウザ（またはシークレットウィンドウ）で同じアカウントにログインする。
   - 同じ写真が出る。
4. もう一度「写真を選択」から別の写真を選ぶ。
   - JPEG・PNG の写真でも手順2〜4を繰り返し、保存と再表示ができる。
   - 新しい写真に変わる。前の写真はサーバーから消える。
5. 「削除」を押す。
   - ホームの右上は人型アイコンに戻り、アカウント画面の行は灰色の丸に戻る。読み込み直しても同じ表示のまま。
   - 写真がないときに「削除」を押しても何も起きない。
6. ブラウザの開発者ツールで通信をオフラインにしてから写真を選ぶ。
   - アプリ内のダイアログ「写真を保存できませんでした」が出て、元の写真に戻る。写真がなかった場合は、ホームの右上は人型アイコン、アカウント画面の行は灰色の丸に戻る。
   - ブラウザで読めない形式のファイルを選んだ場合も同じダイアログになり、JPEG・PNG・WebP の写真を選ぶよう案内する。

## データの持ち方

- 写真の本体は Cloudflare R2 のバケット（`AVATARS` バインディング）に置く。
  - キーは `avatars/<ユーザーID>/<cuid2>.<拡張子>`。差し替えるたびに新しいキーになるので、URL が変わり、古いキャッシュが出ることはない。
  - バケットは公開せず、Worker の `GET /avatars/<ユーザーID>/<ファイル名>` から配信する。ログインなしで読める。写真のURLを知る人は閲覧できる。
- `user.image` には `/avatars/...` の相対パスを入れる。画面と同じオリジンから配信するので、そのまま表示する。
  - `http` で始まる外部の URL が入っていれば、そのまま表示する。削除しても外部の写真には触れない。
- アップロードは `PUT /api/profile/avatar`、削除は `DELETE /api/profile/avatar`。画像のバイナリを JSON に載せないよう、tRPC ではなく素の HTTP で受ける。
  - 受け付けるのは JPEG・PNG・WebP で、5MB まで。宣言された形式と中身の先頭バイトが一致しないものは断る。
  - ブラウザは上げる前に、Canvas で中央を正方形に切り抜き、512px 四方（元の写真が小さければその大きさ）の JPEG に縮める（`apps/web/src/lib/avatar.ts`）。ふつうは数十KB になる。
  - HEIC などブラウザで読み込める写真も JPEG に変換して `Content-Type: image/jpeg` で送る。
  - 新しい写真を保存して `user.image` を書きかえてから、前の写真を消す。途中で失敗しても写真が消えた状態にはならない。
