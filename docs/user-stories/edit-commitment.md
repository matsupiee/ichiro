# コミットメントの詳細を見て、途中で設定を変えられる

> ステータス: 実装済み

## ストーリー

ログイン中のユーザーとして、コミットメントの記録を確かめ、必要なら期間中でも設定を変えたい。
続けるうちに無理のない頻度や金額が分かってくるから。

## 動作確認の手順

`bun run db:seed` でデモデータを入れ、demo@ichiro.app / password123 でログインしておく。

1. メインページで「週3でジムに行って、筋トレ45分と有酸素運動20分をやる」のカードを押す。
   - 「コミットメント詳細」ページが開く。
   - シートの上端からヘッダーまでは標準の14ptの余白になり、背面の画面のステータスバー分の空白が加わらない。
   - 上のカードに連続達成の日数と、今週（月〜日）の7つの丸が出る。報告した日は水色、それ以外は灰色。
   - 今日が報告日で未報告なら「今日の達成を報告する」ボタン、報告ずみなら「今日は報告ずみ　えらいワン」が出る。今日が報告日でなければどちらも出ない。
   - → [今日の達成を報告すると、ワンちゃんが祝福してくれる](./report-achievement.md)
   - 罰金を設定しているなら、その下に「これまでの罰金」の1行の導線が出て、押すと履歴シートが開く。デモデータの「週3でジムに行って、筋トレ45分と有酸素運動20分をやる」は罰金の履歴がないので、シート内は ¥0 と「まだ罰金はないワン。この調子でつづけよう。」になる。
   - → [報告できなかった日は罰金が徴収される](./penalty-collection.md)
2. 下のフォームを最下部までスクロールし、先頭へ戻す。
   - 「コミットメント詳細」のタイトルと戻るボタンはシート上部に固定され、本文だけがスクロールする。
   - 戻るボタンの下に12ptの余白があり、スクロール中も本文がボタンに接しない。
   - 最下部の「変更を保存」まで表示できる。
   - 入力欄を押してキーボードを表示しても、タイトルと戻るボタンは固定されたまま、入力欄が見える位置にスクロールする。
   - 作成ページと同じ項目（コミット内容・頻度・いつまで・罰金・支払い方法）に、今の設定が入っている。
   - コミット内容は長い文章が折り返されて表示される。候補は出ない。
   - 編集後にキーボードの Enter（完了）を押すと、改行を追加せずキーボードが閉じる。入力内容は保持され、変更は「変更を保存」を押すまで保存されない。
   - チェック者の選択や招待リンクの発行は表示されない。
3. コミット内容や罰金の金額を変えて「変更を保存」を押す。
   - 罰金の金額の下に「変更した金額と支払い方法は、今日の報告分から使われます。」と出る。
   - メインページに戻り、変えた内容が一覧に出る。
   - もう一度開くと、変えた内容が残っている。
   - 連続達成と今週の記録は変わらない。
4. 終了日を開始日より前にしようとする。
   - 開始日より前の日付は選べない。

## データの持ち方

- 変更は `commitment` テーブルの同じ行を書きかえる。
  - `start_date` と `user_id` は変えない。
  - 報告の記録（`report` テーブル）はそのまま残る。
  - 保存する前に、締め切りを過ぎた分の罰金を変更前の設定で精算する。そのうえで `settled_through` を昨日にするので、新しい設定は今日の分から使われる。
  - `time_zone` は変更した端末のタイムゾーンに書きかえる。
- 編集用の詳細と報告は持ち主だけが利用できる。

## 対応するテスト

- Enter（完了）で改行せずキーボードを閉じ、変更を保存して再表示できることは `.maestro/commitment-keyboard.yaml` で確認する。既存の `packages/db/src/seed/run.ts` のデモアカウントを使う。
- 詳細は `packages/api/src/routers/consumer/commitment/get/handler.integration.test.ts`、設定の変更は `packages/api/src/routers/consumer/commitment/update/handler.integration.test.ts`
- シート上端の余白、ヘッダーの固定、最下部へのスクロール、キーボード表示中の入力、戻る操作は、既存の `packages/db/src/seed/run.ts` のデモデータを使って iOS Simulator または実機で確認する。
