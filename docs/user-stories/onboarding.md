# アプリを開いたら新規登録とログインを選べる

> ステータス: 実装済み

## ストーリー

未ログインのユーザーとして、アプリを開いたときに「新規登録」と「ログイン」のどちらかを選びたい。
どちらを選んだのか分かる専用の画面で入力したいから。

## 動作確認の手順

ローカルではリポジトリのルートで `bun run dev:server` を起動し、ブラウザで http://localhost:3000/app を開く。
画面と API は同じ Worker から同じオリジンで配信する。API・D1・R2 の定義は `packages/infra/alchemy.run.ts` にまとめ、`alchemy dev` でローカル実行する。起動時にマイグレーションを適用する。
初回はリポジトリのルートで `bun run cloudflare:login` を実行して認証する。
開発時の状態は `.alchemy` 配下に保存し、デプロイ時は Cloudflare の状態ストアを使う。
`apps/web/.env` に認証用の環境変数と Stripe のテストキーを設定する。認証画面だけを確認する場合は、Stripe キーに `sk_test_local_unconfigured`・`pk_test_local_unconfigured`・`whsec_local_unconfigured` を入れて起動できるが、決済は利用できない。
`AUTH_EMAIL_DELIVERY=console` で起動すると、認証コードが開発サーバーのログに `local-auth-email` として出る。
デモデータの作成コマンドは `packages/db/src/seed/run.ts` にある。新規登録の確認はデータが空の状態でも行える。

1. 未ログインのブラウザで http://localhost:3000/app を開く。
   - `/app/welcome` に移り、はじめにの画面（ワンちゃん・ロゴ・説明・「アカウントを作る」「ログイン」ボタン）が表示される。
   - 紹介ページ（http://localhost:3000/）の「はじめる」「さっそくはじめる」「アカウントを作ってはじめる」を押しても、同じはじめにの画面に移る。→ [アプリのサービス内容をログインせず確認できる](./view-service-introduction.md)
   - `/app` や `/app/commitments/new` などのアドレスを直接開いても `/app/welcome` に戻され、ホームやコミットメントの画面に到達できない。
   - ワンちゃんを押すと少しのあいだ跳ねる。振動はない。
   - 待機中と跳ねている間のどちらも、尻尾の根元が体につながったまま揺れる。数周期見て、体との間に隙間ができないことを確認する。
   - OS の「視差効果を減らす」（`prefers-reduced-motion`）を有効にすると、ワンちゃんは動かない。
2. 「アカウントを作る」を押す。
   - 新規登録画面（`/app/sign-up`。名前・メールアドレス・パスワード）に移る。
   - ログインのフォームは同時に表示されない。
   - 空のまま「登録する」を押すと「名前を入力してください」と表示され、登録されない。
3. はじめにの画面に戻り、「ログイン」を押す。
   - ログイン画面（`/app/sign-in`。メールアドレス・パスワード）に移る。
   - 新規登録のフォームは同時に表示されない。
   - まちがったパスワードでは、エラーが表示されてログインできない。
4. 各画面の下部のリンク（「アカウントをお持ちの方はこちら」「はじめての方はこちら」）を押す。
   - もう一方の画面に切り替わる。
5. 各画面のヘッダーの戻るボタンを押す。
   - はじめにの画面に戻る。
6. 登録またはログインする。
   - 新規登録と未確認ユーザーのログインはメール確認画面（`/app/verify-email`）へ進む。6桁コードの確認後にホームへ進む。
   - 確認済みユーザーはパスワードでログインしてホーム（`/app`）へ進む。
   - → [メールアドレスを確認して利用を始められる](./verify-email.md)
   - 通信に失敗した場合はエラーが表示され、サーバーの復旧後に送信し直せる。
   - → [メインページでコミットメントを一覧できる](./commitment-list.md)
7. ログインしたまま `/app/welcome` や `/app/sign-in` を開く。
   - ホームへ移る。
8. 右上のアカウントのボタンを押してアカウント画面を開き、「ログアウト」を押す。
   - はじめにの画面に戻る。
   - → [アカウント画面でアカウントを管理できる](./profile-sheet.md)

## データの持ち方

- 認証は Better Auth のメールアドレス + パスワード。`user`・`account`・`session` テーブルを使う。
  - セッションは HttpOnly の Cookie に入れる（SameSite=Lax）。
- 画面の切り替えはセッションとメール確認状態で決まる。
  - `apps/web/src/routes/app/route.tsx` が画面を開くたびにサーバーでセッションを取得する。
  - `apps/web/src/routes/app/_member.tsx` は、未ログインなら `/app/welcome`、メール未確認ならメール確認画面へ移す。
  - `apps/web/src/routes/app/_guest.tsx` は、確認済みのログイン中ユーザーを `/app` へ移す。

## 対応するテスト

- `apps/web/e2e/onboarding.spec.ts`：はじめにの画面の表示、未ログインでの `/app` 配下からの移動、新規登録とログインの切り替え、入力チェック、ログアウト。
- `packages/api/src/test/auth.integration.test.ts` で、新規登録・セッション取得・ログアウト・再ログインと不正なパスワードの拒否を確認する。
- ログインしていないと API を呼べないことは `packages/api/src/routers/consumer/commitment/list/handler.integration.test.ts` の「ログインしていないと一覧できない」で確かめる。
- ワンちゃんの尻尾の動きと `prefers-reduced-motion` での停止はブラウザで目視で確認する。
