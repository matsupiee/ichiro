# 新しいメールアドレスを確認して変更できる

> ステータス: 実装済み。

## ストーリー

ログイン中のユーザーとして、新しいメールアドレスを入力し、そこに届くコードだけでメールアドレスを変更したい。
現在のアドレスが使えなくなっても、受信できるアドレスに変更するため。

## 動作確認の手順

[認証メールの開発手順](../development/auth-email.md)でメールの受信環境を準備する。
`db:seed:email-verification` に `--verified` を付けると、変更確認用のログイン可能なユーザーを作成できる。

1. ログインしてプロフィールシートの「メールアドレス」を押す。
   - 現在のアドレスが表示され、新しいアドレスを入力できる。
2. 新しいアドレスを入力して「認証コードを送る」を押す。
   - 新しいアドレスだけに6桁のコードが届く。旧アドレスへの送信・確認やパスワードの再入力はない。
   - 現在と同じアドレスや不正な形式では送信できない。
3. 届いたコードを入力し「確認して変更する」を押す。
   - 正しいコードで変更が完了し、新しいアドレスが表示される。
   - 別のアドレス宛て・期限切れ・使用済みのコードは使えない。
   - 再送は60秒後から可能で、新しいアドレスへ送る。
   - 完了するまで登録アドレスは変わらず、途中で戻っても旧アドレスでログインできる。
4. ホームへ戻り、プロフィールのアドレスを確認する。
   - 新しいアドレスが表示される。
5. ログアウトし、新しいアドレスと既存のパスワードでログインする。
   - ログインでき、旧アドレスではログインできない。

## データの持ち方

- 変更完了時に `user.email` を更新し、`emailVerified` を維持する。
- `verification` に変更元・変更先の組に対応するコードのハッシュを保存する。
  - 有効期限は5分、誤入力は5回まで。送信・確認にはログインが必要。
  - 再送・APIの回数制限は Better Auth の標準処理を使う。

## 対応するテスト

- `packages/api/src/test/auth.integration.test.ts`：新アドレスだけへの送信、再送、未ログインの拒否、コードの制約、変更前のアドレスの維持、変更後のログイン。
- `.maestro/change-email-request.yaml` と `.maestro/change-email-confirm.yaml`：ネイティブアプリで送信から変更完了まで。
