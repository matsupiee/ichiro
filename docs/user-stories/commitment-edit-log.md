# コミットメントの変更前の設定を調査できる

> ステータス: 実装済み。API の回帰テストと、iOS Simulator での編集・保存の画面確認済み。

## ストーリー

コミットメントを利用するユーザーとして、罰金設定を変えた後に問題が起きた場合、変更前の設定を運営に調べてもらいたい。
いつ、どの設定から変わったかを記録しておき、金額や支払い方法の食い違いを確認できるようにするため。

## 動作確認の手順

ローカル DB に `bun run db:seed -- --url file:/tmp/ichiro-log-qa.db --commitment-log` を実行すると、デモデータと罰金設定を2回変更した履歴を作れる。
ネイティブアプリと接続する場合は、接続先のローカル D1 のパスを指定する。Alchemy が移行済みなら `--skip-migrations` を付ける。

1. iOS Simulator または実機でデモユーザーとしてログインし、「広東語マスター」の詳細を開く。
   - 現在の罰金は1,500円になっている。
2. 罰金額やコミット内容を編集して保存する。
   - 保存後の内容が表示される。
   - → [途中で設定を変えられる](./edit-commitment.md)
3. 運営用の DB 接続で `commitment_log` を対象の `commitment_id` で絞り、`id` の昇順で確認する。
   - `snapshot` に変更直前の全項目が残り、`logged_at` で更新時刻が分かる。
   - 複数回変更しても以前の履歴が上書きされない。
   - 罰金額、支払い方法、頻度、期間、タイムゾーン、精算済み日付を確認できる。
4. 不正な入力や他人のコミットメントの更新を API で試す。
   - 更新が拒否され、編集の履歴は増えない。
   - DB の更新が失敗した場合、その更新の履歴も残らない。履歴保存に失敗した場合は元の更新も失敗する。

## データの持ち方

- `commitment_log` は `commitment` の UPDATE ごとに旧値を保存する。
  - `id` は連番、`commitment_id` は元データの ID、`logged_at` は保存日時、`snapshot` は旧値の JSON。
  - JSON のキーは Drizzle のプロパティ名で、日時は epoch milliseconds、曜日・月の日付は配列で保存する。
  - DB トリガーで更新と同じステートメント内に記録し、同時更新でも実際の旧値を保存する。
  - 精算ジョブの更新や同じ値を保存する UPDATE も記録する。新規作成・削除そのものは記録しない。
  - 外部キーによる削除を連動させず、コミットメント・ユーザー・支払い方法の削除後も履歴を保持する。
  - 導入前の編集履歴は復元しない。履歴表示用のアプリ画面・公開 API は設けない。
  - commitment の列を追加・削除するときは、トリガーの JSON 項目も新しいマイグレーションで更新する。
- 罰金計算は従来どおり `commitment` と `penalty` を使う。履歴の追加で徴収ルールは変更しない。
