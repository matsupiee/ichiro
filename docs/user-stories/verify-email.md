# メールアドレスを確認して利用を始められる

> ステータス: 実装済み。

## ストーリー

登録するユーザーとして、自分のメールアドレスに届いたコードを使って登録を完了したい。
自分が受信できるアドレスをアカウントに登録するため。

## 動作確認の手順

[認証メールの開発手順](../development/auth-email.md)で送信方法とデータを準備する。

1. iOS Simulator または実機で新規登録する。
   - `ichiro <noreply@mail.ichiro.app>` から6桁のコードが届き、確認画面へ進む。
   - コードを確認するまではメイン画面や保護された API を利用できない。
2. 誤ったコードを入力する。
   - エラーになり、未認証のままになる。
   - 5回間違えると正しいコードでも利用できなくなる。
3. 60秒待ち、コードを再送する。
   - 新しいコードが発行され、古いコードは使えなくなる。
   - 同じアドレスへの送信は1時間に5回まで。別IPやアプリ再起動で制限を回避できない。
4. 最新のコードを5分以内に入力する。
   - 確認が完了してメイン画面へ進む。同じコードは再利用できない。
   - 招待リンクから登録した場合は招待画面へ戻れる。
   - → [友達にチェックを依頼できる](./invite-friend.md)
5. ログアウトし、メールアドレスとパスワードでログインする。
   - 確認済みの場合はコードの再入力を求めない。
   - 同一IPでのログイン試行は60秒に10回まで。
6. 未認証のデータでログインする。
   - パスワードが正しい場合は確認画面に進み、再送して再開できる。
   - 以前発行された未認証セッションが残っていてもメイン機能を利用できない。
7. テストの送信処理を失敗させる。
   - 送信成功として扱わず、未認証のままで再送から再開できる。

## データの持ち方

- `user.emailVerified` が確認済みの状態を表す。
- `verification` はコードの秘密鍵付きハッシュ、有効期限、試行回数を持つ。
  - 有効期限は5分、誤入力は5回まで。コードを消費する処理は原子的に行う。
- `auth_rate_limit` はIPやメールアドレスから生成した秘密鍵付きハッシュ、回数、期限を持つ。
  - D1 に保存し、Worker の再起動後も制限を維持する。期限切れの行は定期処理で削除する。
- これは登録メールアドレスの確認であり、通常のログインに毎回二要素認証を要求する仕様ではない。
