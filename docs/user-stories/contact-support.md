# メールで問い合わせ・報告できる

> ステータス: 実装済み。回帰テストと iOS Simulator でのアプリ起動は確認済み。画面操作ツールが Simulator に接続できないため、タップ操作とメール作成画面への遷移は未確認。

## ストーリー

ログイン中のユーザーとして、マイページから運営へ問い合わせや不具合の報告を送りたい。
困ったときに、送付先を調べずに相談できるようにするため。

## 動作確認の手順

1. 既存の `packages/db/src/seed/run.ts` のコマンド `bun run db:seed --url file:/tmp/ichiro-contact.db` で確認用ユーザーを作成する。
   - アプリから接続する開発用 DB を使う場合は、その接続先を `--url` に指定する。
2. iOS Simulator または実機でネイティブアプリを起動し、デモユーザーでログインする。
3. 右上のプロフィールアイコンからアカウントのシートを開き、「問い合わせ・報告」を押す。
   - メールアプリが利用できる端末では、宛先 `btq32jh@icloud.com`、件名「ichiro 問い合わせ・報告」のメール作成画面が開く。
   - 本文に問い合わせや報告の情報を入力できる。送信は利用者がメールアプリで行う。
   - アカウント情報や支払い情報は自動で本文に追加されない。
4. メール作成をキャンセルしてアプリへ戻る。
   - アカウントのシートを引き続き操作でき、再度メール作成を開ける。
5. メールアプリを利用できない端末でも「問い合わせ・報告」を押す。
   - エラーの案内に送付先 `btq32jh@icloud.com` が表示される。
   - 案内を閉じてアプリを引き続き利用できる。
6. `bun run test` で既存ストーリーの回帰テストを実行する。

## データの持ち方

- `apps/native/lib/contact.ts` に宛先と件名を持ち、`mailto:` で端末のメールアプリに渡す。
- 新しい API や DB テーブルは追加しない。確認用データには既存の seed コマンドを使う。
- 特定商取引法に基づく表記と同じ問い合わせ先を使用する。利用規約の問い合わせ先の参照と、プライバシーポリシーの問い合わせ対応の利用目的を維持する。

## 対応するテスト

- メール作成への遷移と開けない場合の案内はネイティブアプリで確認する。
- 問い合わせ先と法定文書の案内は `apps/web/src/server/public-page.test.ts` で確認する。
- 既存ストーリーの回帰確認は `bun run test` で実行する。
