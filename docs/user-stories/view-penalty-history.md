# 必要なときだけ罰金の履歴を開く

> ステータス: 実装済み

## ストーリー

コミットメントに取り組むユーザーとして、詳細画面では報告や設定に集中し、罰金の合計と履歴は必要なときに開きたい。

## 動作確認の手順

リポジトリのルートで `bun run dev:server` を起動し、`bun run --cwd packages/db db:seed:e2e` でデモデータを入れる。
ブラウザで http://localhost:3000/app を開き、demo@ichiro.app / password123 でログインする。

1. 罰金履歴のある「毎日30分広東語を練習する」の詳細を開く。
   - 連続達成の下には「これまでの罰金」と矢印の1行だけが出る。合計・回数・履歴は出ない。
2. コミット内容を編集し、保存せず「これまでの罰金」を押す。
   - 下からシートが開き、合計・回数・日付・金額・徴収状況が見られる。デモデータでは ¥1,000、2回で、2日分が「徴収ずみ」で出る。
   - 履歴が長い場合はシートの中でスクロールできる。
   - 状況は「徴収ずみ」「徴収待ち」「処理中」「徴収できませんでした」のどれかで、徴収に失敗した行には理由も出る。
3. シートの戻るボタンで閉じる。
   - 詳細画面に戻り、編集中のコミット内容が保持される。
   - もう一度開き、Esc キーやシートの外側（暗くなった部分）のクリックでも閉じられる。閉じたあともう一度開ける。
4. 詳細画面を保存せず閉じ、罰金履歴のない「禁煙する」の詳細で「これまでの罰金」を押す。
   - シートに ¥0、0回と「まだ罰金はないワン。この調子でつづけよう。」が出る。
5. 罰金未設定かつ履歴のないコミットメントの詳細を開く。
   - 「これまでの罰金」の導線が出ない。
   - 過去の履歴があれば、現在の罰金設定がオフでも導線から確認できる。

## データの持ち方

- 既存のコミットメント詳細 API の `penaltyTotal` と `penalties` を使う。
- 開閉状態は画面内に持ち、編集フォームの値は変更しない。
- シートは `<dialog>` で開く（`apps/web/src/components/penalty-history.tsx`）。
- 徴収条件、支払い、個人情報の扱いは変更しない。

## 対応するテスト

- `apps/web/e2e/commitments.spec.ts`：シートの合計・回数・状況、罰金のないコミットメントでの ¥0 の表示、戻るボタンと Esc キーで閉じること、閉じたあとも編集中の内容が残ること。
- API の金額と履歴は既存の `packages/api/src/routers/consumer/commitment/get/handler.integration.test.ts` で確認する。
- 全ストーリーの回帰確認は `bun run test` と `bun run test:e2e`。
