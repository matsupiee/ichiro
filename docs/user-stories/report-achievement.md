# 今日の達成を報告すると、ワンちゃんが祝福してくれる

> ステータス: 実装済み

## ストーリー

ログイン中のユーザーとして、今日やるべきことをやったら、すぐに報告したい。
報告するとワンちゃんが出てきて祝ってくれるので、また明日も続けたくなるから。

## 動作確認の手順

リポジトリのルートで `bun run dev:server` を起動し、`bun run --cwd packages/db db:seed:e2e` でデモデータを入れる。
ブラウザで http://localhost:3000/app を開き、demo@ichiro.app / password123 でログインしておく。

1. メインページで「毎日30分広東語を練習する」の水色の点々の輪のボタンを押す。
   - アプリ内の確認ダイアログに「達成済みにしますか？？」と、対象のコミット内容が出る。詳細ページには移らない。
   - ボタンは「キャンセル」と、水色の「達成済みにする」の2つ。
   - この時点では報告されず、お祝い画面も出ない。
2. 「キャンセル」を押す。
   - ダイアログが閉じ、未報告の表示と残り件数は変わらない。
   - Esc キーで閉じたときも、キャンセルと同じ扱いになる。
3. もう一度点々の輪のボタンを押し、「達成済みにする」を押す。
   - 確認ダイアログが閉じ、すぐに全画面の白いお祝い画面が出る。サーバーの応答は待たない。
   - ワンちゃんが下から跳ねて出てくる。勉強バージョンと筋トレバージョンを、2回の報告で1回ずつ、ランダムな順番で表示する。
   - 勉強バージョンは、青いペンとノートを持つ4コマが順番に、1周1.2秒で繰り返される。
   - 筋トレバージョンは、ピンクのダンベルを持つ3コマが「下げる → 途中 → 上げる → 途中」の順に、1周1.2秒で繰り返される。
   - 10秒以上待っても選ばれたバージョンは変わらず、もう片方の画像は混ざらない。画像が消えたり、二重に重なったりしない。
   - 白い背景に紙吹雪が舞う。ワンちゃんの後ろに水色の放射線は表示されない。
   - 「「毎日30分広東語を練習する」今日も達成！」と、連続達成のタイル（8日）が出る。
   - 「ワン！」の吹き出し、「やったワン！」の見出し、「守った罰金」のタイルは出ない。
   - OS の「視差効果を減らす」（ブラウザの `prefers-reduced-motion: reduce`）が有効な場合は、アニメーションと紙吹雪を止め、ワンちゃんは最初のコマで止まる。
4. 「つづける」を押す。
   - お祝い画面が閉じる。Esc キーでも閉じられる。
   - 次の達成報告では最初のコマから再生される。
   - ページを開いているあいだは、一覧と詳細のどちらから報告しても抽選の順番を共有する。2回ごとに順番を抽選し直すため、同じバージョンの連続は最大2回になる。ページを再読み込みすると新しい組から始まる。
   - 「毎日30分広東語を練習する」の点々の輪が、同じ直径36px の水色の塗りつぶしと白いチェックに変わる。
   - 「今日の報告 あと◯件」が1つ減る。
5. 「毎日30分広東語を練習する」のカードを押して詳細ページを開く。
   - 「今日は報告ずみ　えらいワン」と表示され、報告ボタンは出ない。
   - 今週の丸のうち、今日の分が水色になっている。
6. 未報告のコミットメントの詳細ページで「今日の達成を報告する」を押す。
   - メインページから報告したときと同じお祝い画面が出る。確認ダイアログは出ない。
7. 通信できない状態で報告する（ブラウザの開発者ツールでオフラインにするなど）。
   - お祝い画面は出るが、アプリ内のダイアログ「報告できませんでした」と理由が出て、一覧は再取得で報告前の状態に戻る。
   - 締め切りを過ぎた日の報告を送ったときも、同じダイアログに「締め切りを過ぎたため報告できません」と出る。
   - → [報告できなかった日は罰金が徴収される](./penalty-collection.md)

## データの持ち方

- 筋トレの3枚と勉強の4枚の画像を `apps/web/public/images/celebration/` から配信し、選ばれたバージョンの画像がすべて読み込めてからループを始める。
  - 2種類を1組として表示順を抽選し、次に表示する残りの種類をページのメモリに保持する（`apps/web/src/lib/achievement-animation.ts`）。達成報告時に選んだ結果をお祝い画面の状態に保持する。再描画やループごとの再抽選はしない。
  - 選ばれたバージョンの画像だけを描画する。
  - 表示だけの仕組みで、API・保存データ・料金・個人情報の取り扱いには関わらない。
  - 確認用データは既存の `packages/db/src/seed/run.ts`（E2E では `packages/db/src/seed/e2e.ts`）で作成する。
- `report` テーブルに、報告した日（ユーザーの現地日付 `YYYY-MM-DD`）を1行ずつ持つ。
  - 同じコミットメント・同じ日の報告は1件だけ（`commitment_id` と `report_date` のユニーク制約）。
- 報告する前に、締め切りを過ぎた分の罰金を精算する。精算ずみの日（`commitment.settled_through` 以前）には報告できない。
- 報告できるのは、今日がそのコミットメントの報告日のときだけ。
  - 毎日なら期間中の毎日、曜日ごとなら選んだ曜日、月の特定の日なら選んだ日付、1回だけなら実施日。
- 連続達成は、報告日を今日からさかのぼって、途切れずに報告できている回数。
  - 今日がまだ未報告でも、締め切り前なので連続は途切れない。
  - 報告日でない日は数えずに飛ばす。

## 対応するテスト

- `apps/web/src/lib/achievement-animation.test.ts`：順番の抽選境界、2回で両方が出ること、同じ乱数が続いても偏らないこと、同じ種類が3回続かないこと。
- `apps/web/e2e/commitments.spec.ts`：ホームの確認ダイアログ、キャンセル、お祝い画面の表示・終了、確定後の報告ずみ表示と詳細画面、詳細ページから2回報告すると勉強と筋トレが1回ずつ出ること、動きを減らす設定でワンちゃんが止まること。
- 画像の切り替え順序、繰り返し、透過表示、文字やボタンと重ならないことは、ブラウザで目で見て確認する。
- `packages/api/src/routers/consumer/commitment/report/handler.integration.test.ts`
- 連続達成と報告日の計算は `packages/api/src/shared/schedule/schedule.test.ts`
