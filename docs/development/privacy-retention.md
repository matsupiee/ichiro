# 個人情報の保存期間と削除対応

## 決定した運営方針

2026年10月3日に保存期間と削除請求の受付手順を定めた。公開文面は `apps/web/src/server/site/legal.ts` に置く。

| 情報                                               | 保存期限                                                                                        |
| -------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| アカウント、画像、コミット内容、達成報告、変更履歴 | 利用中。退会または本人確認済み削除請求の早い方から30日以内に削除                                |
| 期限切れ認証コード、失効したセッション             | 有効期限・失効から30日以内                                                                      |
| 運営者が管理するアクセス記録、操作制限の記録       | 取得から90日以内                                                                                |
| 問い合わせ記録                                     | 対応終了から1年以内。削除対象の個人情報は先に削除                                               |
| 税務上必要な帳簿、決済、返金記録                   | 対象年分の確定申告期限の翌日から原則7年。法令上異なる起算日・より長い義務がある場合はそれに従う |
| 運営者が管理するバックアップ                       | 元データの削除から90日以内に消去。復元時は削除を再適用                                          |

30日・90日・1年は運営上の上限として選んだもので、法定期間ではない。取引関係の7年は、個人事業の税務帳簿等の保存期間を参考にした運営方針であり、全個人情報を7年残す根拠にはしない。未決済の罰金も一律に税務記録とは扱わない。

具体的な紛争や法令に基づく保全は、対象、根拠、期限、見直し日を記録し、理由のなくなった情報を削除する。Stripe が独自の法的義務で保持する履歴には同社の方針が適用される。

## 実装・運用の状況

この変更は方針・文面の確定であり、保存期限の自動清掃やアカウント削除ジョブの実装ではない。現行の退会 API はログインと請求の停止までを行い、データを自動削除しない。

公開文面の期限を守るには、運営者による削除運用を開始するか、期限内に削除する仕組みを実装する必要がある。アプリの画面からの削除開始、完了通知、外部サービスの削除、保存用取引記録の分離は別途必要。

現行DBには罰金から user / commitment への削除制約があるため、ユーザー行を直接削除しない。必要最小限の取引記録を分離し、本文を含む commitment_log、認証コード、画像、Stripe の顧客情報まで対象を確認する。既存の退会済みアカウントも対象にする。

## 削除請求の受付と処理

1. 登録メールアドレスから `btq32jh@icloud.com` に件名「個人情報の削除請求」、登録メールと希望する削除範囲を送ってもらう。
   - パスワード・カード番号・認証コードはメールで求めない。
   - 登録アドレスを使えない場合は必要最小限の別の本人確認方法を案内する。
2. 受付から7日以内を目安に返信し、本人確認日、処理期限、担当者を記録する。
3. 退会または本人確認済みの削除請求から30日以内に、削除対象と保持対象を分離して処理する。
   - 未完了の外部サービス処理は追跡し、削除失敗を放置しない。
   - 税務記録として残す情報に目標本文・写真・パスワードを含めない。
4. 完了を通知する。保持する記録があれば、その対象・根拠・期間も案内する。
5. 毎週、退会済みユーザーと削除受付一覧の期限を確認する。ログ等は期限を超える前に削除し、処理記録には元の個人情報をコピーしない。

メール受付は現在の問い合わせ窓口を用いる。

## 国外での取扱い

Resend は米国で主に処理・保存する。Stripe と Cloudflare は米国を含む複数国で処理する。公開情報だけで、このアカウントの実際の全保存先や契約適用状況を確認できたとは扱わない。

公開文面に各社のデータ処理契約・再委託先一覧をリンクする。運営者は実際の契約・設定、再委託先と取扱国を確認し、変更時にも見直す。EU向けの標準契約条項があることだけで、日本の外国第三者提供の要件を満たすと判断しない。必要な同意・情報提供は別途行う。
